# 轨迹规划修改与回归要求

用户在2026-10-14明确要求：以后每次优化轨迹都重复20米／15度完整姿态矩阵。

- 修改搜索、连续连接、速度采样、航道软代价或几何后优化后，必须构建并运行全部规划器单元测试。
- 必须重复开阔水域、起点主航道、起点对向航道三组24×24矩阵。行是相对初始船艏的目标方位，列是目标艏向；0°到345°，每15°；目标距离20m。默认初始u/v/r=4/0/0，终点容差仍30°。
- 测试输入角度在进入float规划API前规范到ROS TF的[-π,π]，正侧方数学残差归零；保留0..345°展示列名，避免等价姿态落在阈值不同侧。
- 每格保存积分轨迹、最终轨迹、尝试速度、无解结果及独立轨迹图；输出完整矩阵PNG、逐行详细PDF和HTML索引。失败项不得删除或只画成功个例。
- 曲率按统一0.25m空间采样计算地面轨迹，不能用船体艏向差替代。默认统计≥3°且≥0.5m的转向段，同时报告1°/5°敏感性，单个S与多个尾部摆动须区分。
- 相同初始条件与预算下对比旧版本；记录新增无解、反向增加、峰值增加及航道外绕代价。有限预算无解不是物理不可达的证明。
- 涉及航道规则时，补做左右镜像、主航道阻塞的安全回退、短距主→对向直接跨道和实际ROS路径/限速配对检查。
- 六状态船模、硬障碍/动态船/COLREG检查保持优先。几何参考不是动态积分轨迹；不能由规划图推断MPC闭环已到达。
- 主航道是任务锁存角色，不是固定左/右，也不一定等同目标所在航道。后续A*航点方向预览仍未启用。

在工作空间根目录构建后运行（每次使用新的输出目录）：

```bash
python3 src/hybrid_a_star_planner/test/run_pose_matrix.py \
  --probe build/hybrid_a_star_planner/pose_matrix_probe \
  --output artifacts/pose_matrix_NEW_VERSION --render \
  --compare artifacts/lane_entry_1014v2/pose_matrix/results.json
```

`--u/--v/--r`用于额外控制变量；`--raw`用于关闭后优化对照。重画已有结果可用`--render-only`；这不代表重新运行规划测试。
