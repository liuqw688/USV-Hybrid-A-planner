# 无人船全局栅格与随船局部观测融合

保留 Fast-Planner 的 SDFMap -> EDTEnvironment -> 搜索/优化/安全检查接口。地图实现分为 `sdf_map_grid.cpp`（初始化、底图、距离场和查询）与 `sdf_map_grid_local.cpp`（船位、局部观测融合及发布），均属于原 SDFMap 类。

## 当前输入约定

- `/map`：静态完整底图，`nav_msgs/msg/OccupancyGrid`，Reliable + Transient Local QoS。
- `/local_map`：传感器生成的局部完整栅格帧，`nav_msgs/msg/OccupancyGrid`，SensorDataQoS。话题可配置。本模块不直接把原始 LaserScan/点云变成局部栅格，需要上游提供该消息。
- `/sdf_map/odom`：无人船实际位置，`nav_msgs/msg/Odometry`，SensorDataQoS；Kino launch 将它映射到与状态机相同的 odom_topic（默认 `/state_ukf/odom`）。
- 所有输入必须实际在配置的 `map` 坐标系中。frame_id保持此前固定配置，不自动修改，不做TF。里程计、目标与地图的数值必须匹配该坐标系。
- 每张栅格的 width/height/resolution/origin 取自对应消息，不固定500m；支持平面原点旋转，不支持倾斜地图。全局大小不按原40x20x5m或5.5m局部范围分配/裁剪。
- 本后端约定 -1 未知、0..100 占据值，>=75算障碍。局部图0..74必须表示已经观测到的非障碍；未观测/遮挡区域必须使用-1，不能填0假装已知空闲。
- 消息为完整底图或局部帧，不订阅输入 `/map_updates`；输出则提供标准 OccupancyGridUpdate 补丁。

## 数据与融合规则

保存四份二维栅格相关数据：共享静态底图、局部历史观测层、融合占据层、膨胀层，以及一份float距离缓存。底图原始消息不修改，也不向输入 `/map` 回发融合结果，避免反馈循环。

1. 静态底图>=75的已知障碍保留，局部空闲不能删除。
2. 对非静态障碍格，局部已知观测覆盖此前局部观测；有效空闲可清除旧局部障碍。
3. 局部未知-1不清除旧值；静态未知可由有效局部观测补充，未被补充的未知仍按障碍。
4. 视场外保留历史值，不因“这次没看到”而清除，不做时间衰减。运动物体离开但未被有效空闲再次观测时，旧局部障碍仍保留。
5. 全局图几何定义不变时，静态底图更新会保留局部层并重建融合结果；尺寸、原点、朝向或分辨率改变时重置局部层。相同底图重复发布不重算距离场（内容比较仍有读取全图的开销）。

## 随船窗口与执行流程

更新窗口为实际船位在map坐标下的 x/y 各 +/-50m，即100m x 100m方形；并非保证传感器看到了整个方形，实际有效观测由局部图中的已知格决定。采用格心是否落在窗口内决定写回范围。旋转栅格的计算包围框可以大于方形，但方形外的格子不写回。

```text
首次 /map -> 保存底图/初始化局部层 -> 全图膨胀和距离缓存初始化一次

实际里程计 -> 更新窗口中心 -> 移入新栅格时标记窗口需要刷新
/local_map -> 检查frame/数据 -> 有界观测队列（最多10帧）
100ms定时回调
  -> 按队列顺序将当前窗口内有效观测融合进全局占据缓存
  -> 仅对窗口及外侧计算余量做距离变换
  -> 只将窗口内膨胀/距离结果写回全局缓存
  -> 窗口外保持原结果
  -> 发布局部补丁，原搜索/优化接口继续查询同一全局缓存
```

没有观测变化且船没有进入新栅格时，不重算距离场。收到重复局部观测仍需检查是否造成占据变化，未改变融合结果时不额外重算。带非零时间戳的乱序局部帧会被拒绝；时间戳为0时按接收顺序处理。队列满时丢弃最旧帧并警告。使用最新里程计与地图世界坐标融合，未实现严格的消息时间同步或传感器新鲜度超时策略。

100ms是检查调度周期，不是已经验证的100ms处理时限。首次全图初始化、后续静态底图确实变化时仍重算全图；局部观测和船移动走局部流程。所有计算仍在原节点回调中同步执行，实际耗时与安全回调被阻塞程度需要仿真测量。

## 局部栅格分辨率与旋转

同分辨率、同朝向且格线对齐时直接映射，避免逐格几何裁剪。允许约1e-4格的浮点对齐容差。

不对齐、不同分辨率或朝向时，以局部格子的四角映射到全局栅格，计算重叠面积：

- 障碍与全局格有正面积重叠就记为障碍，不只采全局格中心，避免遗漏细障碍。
- 只有一个全局格被本帧有效空闲观测完整覆盖，才允许清除该格的旧局部障碍；只覆盖一部分或夹有未知格不清除。
- 同一全局格同时收到空闲和障碍证据时，障碍优先。面积计算使用小量浮点容差，不是连续船体安全证明。

## 距离场：3m膨胀与±10m饱和

用户指定膨胀半径3m，占据阈值75，未知/地图外不可通行。距离场针对膨胀后的二值地图，0..74不产生独立风险权重。

本次用户另确认带符号距离饱和上限10m：障碍外超过10m存+10，障碍内超过10m存-10。远场饱和区梯度为0；10m内保留栅格距离信息。此数值上限不是地图范围、传感器量程或3m膨胀半径。危险阈值1.5m和后端dist0=2m保持原值，均相对膨胀障碍计量。

局部计算框在写回窗口之外增加 `ceil((3m+10m)/resolution)+2` 格的读取余量，用来纳入邻近障碍并完成膨胀/带符号距离计算。局部计算框边缘不是障碍，只有真实全局地图边界补障碍，避免产生随船移动的假墙。只写回100m方形，外侧余量只读。

原getDistance/getInflateOccupancy/evaluateCoarseEDT/evaluateEDTWithGrad接口不变，统一查询融合占据、膨胀和距离缓存。双线性插值及其梯度仍转回map坐标系，第三项为0。距离采用格心和半格边界近似，不等于精确船体轮廓距离。

窗口内对当前融合栅格计算，窗口外是历史缓存，不能宣称全局每个距离始终反映最新局部障碍。船移入新区域会刷新该窗口。特别是局部图中有效空闲不能直接“清空”未知或不可见区域。

## 参数

| 参数 | 当前配置 | 含义 |
|---|---|---|
| sdf_map/use_grid_map | true | Kino启用二维栅格后端 |
| sdf_map/grid_topic | /map | 静态底图输入 |
| sdf_map/grid_local_topic | /local_map | 传感器局部栅格输入 |
| sdf_map/frame_id | map | 固定规划坐标系，无TF |
| sdf_map/grid_local_range | 50m | x/y各方向半宽 |
| sdf_map/grid_distance_cap | 10m | 带符号距离饱和上限 |
| sdf_map/grid_occupied_threshold | 75 | 障碍分类阈值 |
| sdf_map/grid_unknown_is_occupied | true | 未观测未知不可通行 |
| sdf_map/obstacles_inflation | 3m | 各向同性障碍膨胀 |
| sdf_map/grid_snapshot_period | 5s | 有订阅者时全图快照周期，不重算距离场 |
| sdf_map/grid_publish_esdf | false | 可选抽样距离点云 |
| sdf_map/grid_visualization_stride | 10格 | 仅影响距离点云显示采样 |

局部层/融合层和距离缓存常驻全局地图范围，局部更新减少的是计算量，不把全局存储改成滚动小图。核心持久数据约8字节/格：底图1、局部层1、融合层1、膨胀层1、距离4；500m/0.25m约32MB，500m/0.1m约200MB，不含完整消息发布缓存、观测队列、临时矩阵和规划器，峰值更高。分辨率取输入，不自动降采样。

## 输出与RViz

- `/sdf_map/grid_fused`：融合后的全局OccupancyGrid快照，Transient Local。
- `/sdf_map/grid_fused_updates`：map_msgs/OccupancyGridUpdate，全局栅格索引下的局部融合补丁。
- `/sdf_map/grid_inflate`：全局膨胀OccupancyGrid快照。
- `/sdf_map/grid_inflate_updates`：膨胀局部补丁。
- 可选 `/sdf_map/esdf`：抽样PointCloud2，z=0、intensity=距离；局部更新时只显示该计算窗口。

局部更新主要发送补丁，没有补丁订阅者时跳过补丁构造；新全图订阅者出现时发送当前快照，并在有全图订阅者时默认每5秒刷新快照，修复晚加入或错过补丁的显示。全图快照发布与ESDF计算是两回事，不会为发送快照重新做距离变换。完整快照序列化仍有全图开销，可调整周期；地图很大时不要默认高频发布完整图。

RViz Fixed Frame设map，Map显示选择 `/sdf_map/grid_fused` 或 `/sdf_map/grid_inflate`，启用相应更新话题。该输出不覆写输入 `/map`。新增依赖标准消息包 map_msgs（当前机器已有头文件）；换环境时需随package.xml安装依赖。
