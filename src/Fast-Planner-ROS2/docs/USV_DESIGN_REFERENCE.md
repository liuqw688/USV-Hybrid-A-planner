## 二、你的无人船模型：可以直接作为前端状态传播基础

### 2.1 原始模型与参数

PDF 第 1 页定义的状态向量：

\\[ \boxed{ \mathbf X= \begin{bmatrix} x&y&\psi&u&v&r \end{bmatrix}^{T} } \\]

其中：

| 状态         | 含义                   | 单位    |
| ---------- | -------------------- | ----- |
| \\(x,y\\)  | 世界坐标系下的二维位置          | m     |
| \\(\psi\\) | 船体航向角                | rad   |
| \\(u\\)    | 船体坐标系纵向速度（Surge）     | m/s   |
| \\(v\\)    | 船体坐标系横向速度（Sway），向左为正 | m/s   |
| \\(r\\)    | 偏航角速度（Yaw Rate）      | rad/s |

控制输入：

\\[ \boxed{ \mathbf U= \begin{bmatrix} v\_{\rm cmd}\\\ w\_{\rm cmd} \end{bmatrix} } \\]

其中 \\(v\_{\rm cmd}\\) 是前进速度命令，\\(w\_{\rm cmd}\\) 是角速度命令。

特别注意：这里的输入是命令值，而不是实际纵向速度 \\(u\\) 和实际偏航角速度 \\(r\\)。 两者之间存在动态响应过程，不能直接认为：

\\[ u=v\_{\rm cmd},\qquad r=w\_{\rm cmd} \\]

这是你辨识模型的核心价值所在。

### 2.2 完整运动学关系

根据 PDF：

\\[ \boxed{ \begin{aligned} \dot x&=u\cos\psi-v\sin\psi\\\ \dot y&=u\sin\psi+v\cos\psi\\\ \dot\psi&=r \end{aligned} } \\]

将其写成矩阵形式：

\\[ \dot{\boldsymbol\eta} = R(\psi)\boldsymbol\nu \\]

其中：

\\[ \boldsymbol\eta= \begin{bmatrix}x\\\y\\\\\psi\end{bmatrix}, \quad \boldsymbol\nu= \begin{bmatrix}u\\\v\\\r\end{bmatrix} \\]

\\[ R(\psi)= \begin{bmatrix} \cos\psi&-\sin\psi&0\\\ \sin\psi&\cos\psi&0\\\ 0&0&1 \end{bmatrix} \\]

这与船舶领域常用的平面三自由度运动学形式一致。

组合成完整状态方程：

\\[ \boxed{ \dot{\mathbf X}=f(\mathbf X,\mathbf U) = \begin{bmatrix} u\cos\psi-v\sin\psi\\\ u\sin\psi+v\cos\psi\\\ r\\\ -0.433264281u+0.400421432v\_{\rm cmd}+0.032263988\\\ -0.313324916v-0.006741061r-0.407958500w\_{\rm cmd}-0.000993619\\\ 0.166118168v-0.544509453r+0.837536662w\_{\rm cmd}+0.000626529 \end{bmatrix} } \\]

我建议把这个函数作为整个规划系统的统一动力学基础，而不是在 Kinodynamic A\*、Shot Trajectory 和 B 样条优化器中分别实现三套不同的运动模型。

### 2.4 为什么不能继续使用原 `stateTransit()`？

原 Fast-Planner 使用三维双积分器：

\\[ \mathbf p\_{k+1}= \mathbf p_k+\mathbf v_k\Delta t+ \frac12\mathbf a_k\Delta t^2 \\]

它假设加速度在一个运动基元内恒定。

你的模型则存在：

- 纵向速度的一阶响应；
- 横向速度与偏航角速度耦合；
- 航向角变化导致坐标变换矩阵变化；
- 两个命令共同影响三个速度状态。

因此不能简单替换状态变量后继续使用原解析状态转移矩阵。

建议改成：

\\[ \boxed{ \mathbf X\_{k+1} = \operatorname{Integrate} \left(f,\mathbf X_k,\mathbf U_k,\Delta t\right) } \\]

对于初版工程实现，推荐固定步长 RK4（四阶 Runge–Kutta）数值积分。

它允许每段运动基元保持恒定命令，同时准确得多地捕捉船舶航向和横向运动变化。后面会给出完整公式与对应代码结构。

### 3.1 建议保留的架构

无人船起始状态 / 局部目标

\\(X_0=[x,y,\psi,u,v,r]\\)，\\(X_g\\) 或目标区域

船体碰撞检查

动态约束与代价

启发式搜索

目标状态连接

带时间戳的可行状态轨迹

\\(X(t),\ U(t)\\)，而不只是 \\(x,y\\) 路径点

这里有一个重要设计原则：前端不仅要输出空间位置，还要保留产生这段轨迹的命令和时间。

否则后端虽然能画出光滑曲线，却无法知道这条曲线对应的船体运动状态。

### 3.2 修改 `stateTransit()`：改为 RK4 船模积分

对你的模型，采用：

\\[ \dot{\mathbf X}=f(\mathbf X,\mathbf U) \\]

假设每个运动基元持续 \\(\tau\\)，该段命令保持不变。

四阶 Runge–Kutta：

\\[ \begin{aligned} k_1 &= f(X_k,U_k)\\\ k_2 &= f(X_k+\frac{h}{2}k_1,U_k)\\\ k_3 &= f(X_k+\frac{h}{2}k_2,U_k)\\\ k_4 &= f(X_k+hk_3,U_k) \end{aligned} \\]

\\[ \boxed{ X\_{k+1}=X_k+ \frac{h}{6}(k_1+2k_2+2k_3+k_4) } \\]

一段长度为 \\(\tau\\) 的运动基元，可以再划分为多个积分小步 \\(h\\)，从而用于碰撞检查。

建议把动力学单独封装成 `UsvDynamics`，而不是全部写在 `kinodynamic_astar.cpp` 中。

下面给出可作为实现起点的核心 C++ 函数。它直接采用你的 11 个系数，示例仅负责动力学计算，不包含控制限幅、碰撞检测和完整搜索逻辑。

```

#include <Eigen/Dense>
#include <cmath>
#include <algorithm>

using State = Eigen::Matrix<double, 6, 1>;
using Control = Eigen::Vector2d;

// State: [x, y, psi, u, v, r]
// Control: [v_cmd, w_cmd]

State usvDynamics(const State& x, const Control& cmd)
{
    const double psi = x(2);
    const double u   = x(3);
    const double v   = x(4);
    const double r   = x(5);

    const double vc = cmd(0);
    const double wc = cmd(1);

    State dx;

    dx(0) = u * std::cos(psi) - v * std::sin(psi);
    dx(1) = u * std::sin(psi) + v * std::cos(psi);
    dx(2) = r;

    dx(3) = -0.433264281 * u
            + 0.400421432 * vc
            + 0.032263988;

    dx(4) = -0.313324916 * v
            - 0.006741061 * r
            - 0.407958500 * wc
            - 0.000993619;

    dx(5) = 0.166118168 * v
            - 0.544509453 * r
            + 0.837536662 * wc
            + 0.000626529;

    return dx;
}

State rk4Step(const State& x,
              const Control& cmd,
              double h)
{
    const State k1 = usvDynamics(x, cmd);
    const State k2 = usvDynamics(x + 0.5*h*k1, cmd);
    const State k3 = usvDynamics(x + 0.5*h*k2, cmd);
    const State k4 = usvDynamics(x + h*k3, cmd);

    return x + (h/6.0)*(k1 + 2*k2 + 2*k3 + k4);
}

State stateTransit(const State& x0,
                   const Control& cmd,
                   double tau,
                   double max_step = 0.05)
{
    State x = x0;

    // 防止 tau 非法
    if (tau <= 0.0 || max_step <= 0.0)
        return x0;

    const int N = std::max(
        1, static_cast<int>(std::ceil(tau/max_step))
    );

    const double h = tau / N;

    for (int i = 0; i < N; ++i)
    {
        x = rk4Step(x, cmd, h);
    }

    return x;
}

```

这里 `max_step=0.05 s` 只是初始数值积分设置，不是经过你的船体模型验证的最佳值。需要通过减半步长实验检查数值收敛。

另外，真正的搜索节点应当存储积分期间的轨迹采样，或提供能够重放同一运动基元的函数。否则只计算终点状态无法保证中途不碰撞。

### 3.4 时间采样怎么设置

原无人机代码正常扩展时主要使用 `max_tau` 对应的一种持续时间。

对你的船，建议改成多个持续时间，但不要一开始设置得过密。

例如在初步仿真阶段可以比较：

\\[ \tau\in\\{0.5,1.0,2.0\\}\ {\rm s} \\]

它们只是用于实验的候选时间，并非根据 PDF 直接确定的物理最优值。

为什么需要比较？

考虑纵向动力学：

\\[ \dot u=-0.433264281u+\cdots \\]

对应的自由响应时间常数约为：

\\[ T_u=\frac{1}{0.433264281}\approx2.31\ {\rm s} \\]

横荡—偏航子系统的连续时间矩阵：

\\[ A\_{vr}= \begin{bmatrix} -0.313324916&-0.006741061\\\ 0.166118168&-0.544509453 \end{bmatrix} \\]

其特征值约为：

\\[ \lambda_1=-0.3183,\qquad \lambda_2=-0.5396 \\]

对应时间常数约为：

\\[ T_1=3.14\ {\rm s},\qquad T_2=1.85\ {\rm s} \\]

这意味着你的船并不是收到一个角速度命令后，瞬间达到对应角速度。若大量使用极短运动基元，搜索可能反复切换命令，而船舶状态尚未形成明显变化。

因此，积分步长 \\(h\\) 和 运动基元时长 \\(\tau\\) 必须分开设置：

- \\(h\\)：决定动力学积分与碰撞检测精度。
- \\(\tau\\)：决定一次搜索扩展允许命令持续多长时间。

两者不能混为一谈。

### 3.6 `posToIndex()` 和哈希表必须修改

这是一个容易被忽略、但比公式修改更可能导致规划失败的问题。

原版搜索哈希表主要按照空间栅格索引查重，同一位置体素中的不同速度状态可能被合并。

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub



对于无人船，假设两条轨迹到达同一位置：

\\[ X_A=[10,5,0,1,0,0]^T \\]

\\[ X_B=[10,5,\pi/2,1,0,0]^T \\]

虽然空间位置相同，但：

- A 船头朝东；
- B 船头朝北。

它们对下一段轨迹的可达性完全不同。

因此不能再只使用：

\\[ (i_x,i_y) \\]

建议初版采用状态离散：

\\[ \boxed{ I= (i_x,i_y,i\_\psi,i_u,i_r) } \\]

对 \\(\psi\\) 做周期处理：

\\[ i\_\psi= \left\lfloor \frac{\operatorname{wrap}\_{2\pi}(\psi)} {\Delta\psi} \right\rfloor \\]

其他变量：

\\[ i_u=\left\lfloor\frac{u-u\_{\min}}{\Delta u}\right\rfloor \\]

\\[ i_r=\left\lfloor\frac{r-r\_{\min}}{\Delta r}\right\rfloor \\]

横向速度 \\(v\\) 在状态中必须保留。但初版可以尝试采用多个候选标签的方式，减少横向速度离散维度造成的节点爆炸。

例如同一个 \\((i_x,i_y,i\_\psi,i_u,i_r)\\) 栅格保留少量不同 \\(v\\) 状态的候选，而不是简单地只留代价最小的一个。

如果之后发现横荡速度直接影响避障可行性，则应加入：

\\[ i_v=\left\lfloor\frac{v-v\_{\min}}{\Delta v}\right\rfloor \\]

需要明确：省略 \\(i_v\\) 是一种工程近似，会导致不同动力学状态被合并；多标签也不能自动证明搜索完备。

如果采用空间、航向、速度联合离散，搜索规模会显著增加，需要结合局部规划范围、采样数量和节点上限进行性能评估。

## 四、搜索代价：`g_score` 与 `f_score` 如何修改

### 4.1 A\* 的基本结构不需要改

仍然使用：

\\[ \boxed{f(n)=g(n)+\lambda_hh(n)} \\]

`g_score` 是从起点到当前节点累计的实际规划代价。

`h_score` 是当前节点到目标的估计剩余代价。

需要改变的是代价函数的具体内容，而不是 A\* 的组织形式。

### 4.2 为什么原加速度平方代价不能直接沿用

原 Fast-Planner：

\\[ g\_{\rm next} = g\_{\rm current} + (\\|\mathbf a\\|^2+w_t)\tau \\]

这是针对加速度控制建立的代价。

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub



你的输入是：

\\[ [v\_{\rm cmd},w\_{\rm cmd}] \\]

如果直接计算：

\\[ (v\_{\rm cmd}^2+w\_{\rm cmd}^2)\tau \\]

存在两个问题：

第一，速度命令和角速度命令的单位不同，平方后不能不经归一化就直接相加。

第二，船舶想要保持正常巡航需要持续给予一定前进命令；简单惩罚绝对命令幅值可能使规划器不合理地偏向低速或零命令。

### 4.3 推荐第一版代价函数

我的建议是把代价分成时间、巡航速度偏差、转向命令和航道偏好四项。

\\[ \boxed{ J=\int_0^T \left[ w_t+ w_v\left(\frac{v\_{\rm cmd}-v\_{\rm ref}}{V_s}\right)^2+ w_w\left(\frac{w\_{\rm cmd}}{W_s}\right)^2+ w_c\left(\frac{d\_{\rm center}}{D_s}\right)^2 \right]dt } \\]

其中：

- \\(v\_{\rm ref}\\)：期望巡航命令。
- \\(V_s,W_s,D_s\\)：对应的归一化尺度，均须大于零。
- \\(d\_{\rm center}\\)：当前位置到期望航道中心线的距离。
- \\(w_t,w_v,w_w,w_c\\)：非负权重。

对应单个运动基元：

\\[ \boxed{ \Delta g= \int_0^\tau L(X(t),U_k)\\,dt } \\]

由于在每段运动基元中命令恒定，速度和角速度命令项可直接乘以 \\(\tau\\)，但航道距离项应随积分轨迹采样计算。

离散形式：

\\[ \Delta g\approx \sum\_{j=1}^{N} L(X_j,U_k)h \\]

\\[ g\_{\rm new}=g\_{\rm current}+\Delta g \\]

初版还建议将碰撞、船体边界、不可航行区、最大控制输入等设为硬约束，而不是允许规划器通过支付一个有限惩罚就进入危险区域。

等基础搜索稳定之后，再考虑加入：

\\[ J\_{\Delta U}= w\_{\Delta U} \sum_k \left\\| D_U^{-1} (U_k-U\_{k-1}) \right\\|^2 \\]

它可以减少命令频繁切换。

不过这里也有一个算法上的代价：一旦把控制变化率作为优化目标，下一步代价依赖前一段输入，搜索状态或哈希标签也需要记录上一条命令，否则会破坏原先的状态等价关系。

建议第一版先不加入控制变化率代价，等基本前端跑通后再增加。

## 五、启发式函数 `estimateHeuristic()` 应该怎么改

### 5.1 原来的最优控制解析解不能保留

原 Fast-Planner 的启发式函数对应双积分器：

\\[ \dot{\mathbf p}=\mathbf v,\qquad \dot{\mathbf v}=\mathbf a \\]

通过求解：

\\[ \min\int_0^T (\\|\mathbf a(t)\\|^2+w_t)dt \\]

得到最优时间四次方程。

但你的模型是：

\\[ \dot{\mathbf X}=f(\mathbf X,\mathbf U) \\]

它包含三角函数坐标变换以及耦合的速度动力学。

所以原代码中的 `cubic()`、`quartic()` 和四次方程不能直接视为当前无人船问题的精确最优控制解。

我的建议：第一版不要追求复杂的解析启发式，而是先构造正确、计算量小、具有明确代价下界意义的启发式函数。

### 5.2 第一版：基于最短行驶时间的启发式

假设当前位置：

\\[ P=(x,y) \\]

目标位置：

\\[ P_g=(x_g,y_g) \\]

欧氏距离：

\\[ d=\sqrt{(x_g-x)^2+(y_g-y)^2} \\]

如果能够确定船舶对地速度的上界 \\(V\_{\max}\\)，那么：

\\[ T\ge\frac{d}{V\_{\max}} \\]

对于前面设计的非负代价函数：

\\[ L(X,U)\ge w_t \\]

所以：

\\[ J\_{\rm remain}\ge w_tT \\]

因此可以采用：

\\[ \boxed{ h_d(X)=w_t\frac{d}{V\_{\max}} } \\]

这是一个非常适合第一版的启发式函数。

需要注意两点：

第一，\\(V\_{\max}\\) 必须是可信的实际对地速度上界，而不是未经验证地直接把 `v_cmd_max` 当作船体实际速度上限。

第二，只有当总代价确实包含不小于 \\(w_t\\) 的非负单位时间代价时，该式才具有上述下界性质。

如果没有可靠速度上界，宁愿先设置：

\\[ h=0 \\]

以 Dijkstra 式搜索验证基本正确性，也不要使用一个缺乏依据的启发式函数。

### 5.3 第二版：加入航向角约束

对于无人船，航向角会直接影响可达性。

定义航向误差：

\\[ e\_\psi= \operatorname{wrap}\_{[-\pi,\pi]} (\psi_g-\psi) \\]

如果终点航向是硬约束，并且实际偏航角速度满足：

\\[ |r|\le r\_{\max} \\]

那么：

\\[ T\ge\frac{|e\_\psi|}{r\_{\max}} \\]

又因为距离和航向两个条件都必须满足，时间至少为：

\\[ T\_{\min}= \max\left( \frac{d}{V\_{\max}}, \frac{|e\_\psi|}{r\_{\max}} \right) \\]

于是：

\\[ \boxed{ h(X)=w_t \max\left( \frac{d}{V\_{\max}}, \frac{|e\_\psi|}{r\_{\max}} \right) } \\]

这个函数忽略了纵向、横向和偏航动态的耦合，因此通常低估真实剩余时间，但正因为它乐观，适合作为保守的 A\* 启发式。

注意使用实际目标区域时，应扣除允许的位置和航向误差；不能将宽松目标区域错误地当成精确点约束。

### 5.4 为什么不建议直接使用 Dubins 路径作为严格启发式

你可能会想到使用 Dubins 曲线估计剩余路径。

但标准 Dubins 车模假设：

\\[ \dot x=V\cos\psi,\qquad \dot y=V\sin\psi,\qquad \dot\psi=\omega \\]

其中不存在船体横向速度 \\(v\\)。

你的无人船却满足：

\\[ \dot y=u\sin\psi+v\cos\psi \\]

即存在横荡与侧滑。

因此，标准 Dubins 的最小转弯半径条件并不能无条件套用于你的船舶模型。它可以作为探索性的搜索引导，但不能未经验证就认为它是原问题的严格代价下界。

如果后续希望提高搜索效率，我更建议在真实船模的基础上离线构建简化的 cost-to-go 查找表，或者使用局部数值最优控制解辅助搜索。

## 六、`computeShotTraj()`：终端连接要怎样改

### 6.1 为什么原三次多项式不能直接用

原 Fast-Planner 使用：

\\[ p(t)=at^3+bt^2+ct+d \\]

根据起终位置和速度直接求出连接曲线。

[image](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com\&sz=32)

GitHub



对于你的船舶模型，假设分别对：

\\[ x(t),\quad y(t),\quad\psi(t) \\]

使用三次多项式。

虽然可以满足起终的几何位置和航向，但并不能保证满足：

\\[ \dot x=u\cos\psi-v\sin\psi \\]

\\[ \dot y=u\sin\psi+v\cos\psi \\]

以及对应的三条速度动力学。

所以会出现：

生成的轨迹曲线在几何上平滑，但不存在合法的前进与转向命令使你的船严格沿着它运动。

这是必须避免的问题。

### 6.2 第一阶段建议：暂时关闭 Shot Trajectory

先让 Kinodynamic A\* 使用动力学运动基元一直搜索到目标附近。

终止条件不再只检查位置，而应至少考虑：

\\[ \\|P-P_g\\|\le\varepsilon_p \\]

\\[ |\operatorname{wrap}(\psi-\psi_g)| \le\varepsilon\_\psi \\]

如果还需要停船或以特定速度抵达：

\\[ |u-u_g|\le\varepsilon_u \\]

\\[ |v-v_g|\le\varepsilon_v \\]

\\[ |r-r_g|\le\varepsilon_r \\]

其中，终点位置、航向、速度是否全部需要精确满足，应该由任务场景决定。

例如：

- 普通航路点：可能只需到达一定区域且航向合理。
- 航道通行：更关注通过方向与速度。
- 靠泊：通常需要较严格的航向、位置和低速约束。

不应该给所有规划目标都设置相同的六维终端状态。

需要保留 Fast-Planner 原有的局部规划逻辑：到达搜索 `horizon` 可以返回一段局部有效轨迹，不必每次重规划都抵达全局目标。

### 6.3 第二阶段：设计基于模型预测的 Shot Trajectory

当距离目标比较近时，设计一个局部闭环连接器。

例如：

当前六维状态 \\(X_0\\)

计算目标航向、距离及速度误差

局部控制律 / 短时优化生成命令

使用真实辨识模型逐步积分

检测碰撞、控制限幅和终端误差

成功：保存整段命令与状态轨迹

可以采用两种技术路线：

路线 A：控制律加前向积分。 使用 LOS（视线引导）或姿态—速度反馈控制生成短时命令，通过你的船模积分得到轨迹。实现简单，适合第一版。

路线 B：短时最优控制或 Multiple Shooting。 把终端连接写成一个小规模优化问题，寻找多个分段命令，使最终状态尽量接近目标。

例如：

\\[ \min\_{\mathbf U_0,\ldots,\mathbf U\_{N-1}} \left[ \\|P_N-P_g\\|\_{Q_p}^2+ e\_{\psi,N}^2q\_\psi+ \\|\nu_N-\nu_g\\|\_{Q\_\nu}^2+ \sum\_{k=0}^{N-1}\ell(X_k,U_k) \right] \\]

约束：

\\[ X\_{k+1}=F_h(X_k,U_k) \\]

\\[ U\_{\min}\le U_k\le U\_{\max} \\]

\\[ X_k\in\mathcal X\_{\rm safe} \\]

这里 \\(F_h\\) 就是你已经建立的数值积分传播器。

求解完成后，只有终端误差、动力学和安全约束均满足要求，才声明 Shot 成功。

我的建议是：第一版直接关闭 Shot；前端搜索稳定后，再增加基于船模的短时连接器。 不建议在最初阶段同时调试搜索、Shot 和 B 样条，否则规划失败很难定位到具体模块。

## 七、无人船环境与碰撞检测怎么改

这部分实际上比单纯更换动力学方程还重要。

### 7.1 地图：从三维空域变为二维水面可航行区域

原 Fast-Planner 面向 UAV，地图查询使用三维点：

\\[ P=(x,y,z) \\]

不能简单地将：

\\[ z=\psi \\]

来复用地图接口。

因为 \\(z\\) 表示物理高度，\\(\psi\\) 表示航向，两者的物理含义和单位都不同。

推荐将其拆开：

\\[ P=(x,y) \\]

\\[ X=(x,y,\psi,u,v,r) \\]

使用二维水面障碍地图，或者在暂时保留三维地图接口时使用固定水面高度切片。

但这里还需要考虑：

- 航道边界与水陆边界；
- 禁航区和浅水区；
- 未知区域的安全策略；
- 地图坐标系和定位坐标系；
- 障碍物膨胀与船体尺度。

### 7.2 不能只检查船体中心点

对于无人船，船体有长度、宽度和航向。

建议采用二维船体多边形或多个圆近似实际占用区域。

若采用船体局部坐标中的某个顶点：

\\[ p_i^B= \begin{bmatrix} x_i^B\\\y_i^B \end{bmatrix} \\]

则世界坐标顶点：

\\[ \boxed{ p_i^W= \begin{bmatrix}x\\\y\end{bmatrix} + R_2(\psi)p_i^B } \\]

其中：

\\[ R_2(\psi)= \begin{bmatrix} \cos\psi&-\sin\psi\\\ \sin\psi&\cos\psi \end{bmatrix} \\]

在每一个积分采样状态中检查变换后的船体与障碍物是否相交。

只检查中心点，可能忽略船体边缘

考虑朝向与船体外形，检测更完整

还要考虑运动基元中间的“扫掠体积”。只在每个 RK4 积分步末端检查船体轮廓，仍可能漏掉两帧之间的碰撞。

可以通过自适应采样、线段扫掠近似或保守安全膨胀处理。

### 7.3 对你已有的 COLREGs 避碰目标，需要额外模块

你的船模可以回答：

> 施加这个控制命令后，无人船会怎么运动？

但它不能回答：

> 与其他船相遇时，应该从哪一侧避让？

后者属于行为决策与规则约束。

需要单独考虑会遇分类、让路责任、目标船预测和安全距离，再将它们接入轨迹搜索。

例如对遇、交叉、追越与直航船规则，分别涉及 COLREGs 第 13–17 条。规则还要求结合具体会遇条件，而不是简单地将所有情况编码成“只能右转”。

[image](https://www.google.com/s2/favicons?domain=https://www.imo.org\&sz=32)

国际海事组织



因此我建议分层：

\\[ \text{会遇识别与规则决策} \rightarrow \text{安全航行区域和行为约束} \rightarrow \text{Kinodynamic A\*} \\]

搜索前端负责在给定行为约束下生成可执行轨迹。

如果加入目标船动态避碰，节点还需要时间维度：

\\[ X\_{\rm search}=(x,y,\psi,u,v,r,t) \\]

并且必须评估目标船在对应时刻的位置和安全占用区域。仅将 `dynamic=true` 打开，并不能自动获得完整的动态避碰能力。

## 八、最关键的问题：后端 B 样条到底要如何接入？

这一部分我认为需要单独认真设计。

因为 Fast-Planner 的前端和后端原本是为无人机配套设计的，而不是一个天然适用于所有动力学模型的通用系统。

### 8.1 先看原来的 B 样条优化器做了什么

`planner_manager.cpp` 原始调用链：

```
kino_path_finder_->getSamples(
    ts, point_set, start_end_derivatives);

NonUniformBspline::parameterizeToBspline(
    ts, point_set, start_end_derivatives, ctrl_pts);

ctrl_pts = bspline_optimizers_[0]
    ->BsplineOptimizeTraj(...);
```

接着调用：

```

pos.checkFeasibility(false);
pos.reallocateTime();
```

源码中的 `BsplineOptimizer::NORMAL_PHASE` 主要包含平滑度、障碍距离和运动可行性代价，而可行性代价根据位置控制点之间的一阶和二阶差分计算速度、加速度超限惩罚。

+2



也就是说，原后端核心优化对象是：

\\[ \mathbf p(t)= \sum\_{i=0}^{n}N\_{i,p}(t)\mathbf Q_i \\]

其中 \\(\mathbf Q_i\\) 为 B 样条控制点。

它可以对几何轨迹进行平滑，但没有直接约束：

\\[ \dot v=a\_{11}v+a\_{12}r+b_vw\_{\rm cmd}+c_v \\]

所以不能因为它通过了 `checkFeasibility()`，就认为它满足你的无人船动力学。

### 8.2 我建议考虑两条路线

方案 A：保留位置 B 样条，增加船模验证

建议先实现

前端真实船模搜索 → 位置与航向参考拟合 → B 样条平滑 → 根据船模检查命令是否可实现 → 合格则交给控制器

优点：修改量较小，能够较快复用原 Fast-Planner 的优化框架，也方便分别测试前端、优化器和控制器。

局限：后端优化生成的曲线不能天然保证动力学可行；验证不通过时必须有重新优化或回退机制。

方案 B：基于船舶动力学约束进行 B 样条优化

前端真实船模搜索 → 初始化状态与控制曲线 → 将船舶动力学写入优化约束 → 优化并验证

优点：前后端模型一致，可以把横荡、偏航响应与控制限幅直接纳入优化目标或约束。

局限：需要较大幅度改造原 B 样条优化器，涉及非线性约束、梯度计算和求解稳定性。

我的选择是：先实现 A，把系统拆成可验证的模块；最终如果追求高动态精度和可靠控制，再逐步升级到 B。

这比一次性重写前后端更容易找到问题来源。

## 九、方案 A：最小改动接入 B 样条

### 9.1 前端应该输出哪些信息？

不能只返回：

```
std::vector<Eigen::Vector3d> positions;
```

建议至少输出：

```
struct UsvTrajectorySample
{
    double time;
    State state;       // x,y,psi,u,v,r
    Control command;   // v_cmd,w_cmd
};
```

每一个采样点都具有时间、六维状态和对应控制命令。

再从中提取：

\\[ P(t)=[x(t),y(t)]^T \\]

和独立航向参考：

\\[ \psi(t) \\]

注意：不应该直接把 \\((x,y,\psi)\\) 伪装成原来的 \\((x,y,z)\\) 传入未经修改的三维 B 样条优化器。

因为原优化器认为三个维度使用相同的空间距离、速度和加速度约束。但 \\(x,y\\) 的单位是米，\\(\psi\\) 是弧度。

正确的初步实现是：

- 位置 B 样条负责 \\(x,y\\)。
- 航向曲线独立表示和优化。
- 航向需要先做连续化（unwrap），避免从 \\(179^\circ\\) 到 \\(-179^\circ\\) 时出现错误的大角度旋转。
- 后处理检查位置曲线和航向曲线是否能够由真实船模共同实现。

### 9.2 前端末端导数要如何提供？

原版 `getSamples()` 会给 B 样条参数化提供起终速度和加速度。

你的无人船没有办法直接使用：

\\[ [u,v,r] \\]

来代表世界坐标下的位置导数。

必须根据运动学转换。

一阶导数：

\\[ \dot P= \begin{bmatrix} u\cos\psi-v\sin\psi\\\ u\sin\psi+v\cos\psi \end{bmatrix} \\]

二阶导数：

\\[ \boxed{ \begin{aligned} \ddot x={}& \dot u\cos\psi-\dot v\sin\psi-r\dot y\\\ \ddot y={}& \dot u\sin\psi+\dot v\cos\psi+r\dot x \end{aligned} } \\]

其中：

\\[ \dot u,\dot v,\dot r \\]

由你的 11 参数动力学模型计算得到。

所以前端应当为位置 B 样条输出：

\\[ P_0,\ \dot P_0,\ \ddot P_0 \\]

\\[ P_T,\ \dot P_T,\ \ddot P_T \\]

同时独立传递：

\\[ \psi_0,r_0,\dot r_0 \\]

以及末端对应状态。

这里还应注意：在优化开始后，如果改变了末端曲线的导数，应该重新验证它与原搜索末端状态的一致性。

### 9.3 后端修改后，怎样验证动力学可行性？

假设位置 B 样条给出：

\\[ x(t),y(t) \\]

航向曲线给出：

\\[ \psi(t) \\]

那么：

\\[ u(t)= \dot x\cos\psi+\dot y\sin\psi \\]

\\[ v(t)= -\dot x\sin\psi+\dot y\cos\psi \\]

\\[ r(t)=\dot\psi \\]

这样就可以根据平滑曲线恢复船体速度状态。

继续求导：

\\[ \boxed{ \begin{aligned} \dot u={}&\ddot x\cos\psi+\ddot y\sin\psi+rv\\\ \dot v={}&-\ddot x\sin\psi+\ddot y\cos\psi-ru\\\ \dot r={}&\ddot\psi \end{aligned} } \\]

然后代入你真实的动力学模型，反求所需控制输入。

从纵向动力学：

\\[ \dot u=-0.433264281u+ 0.400421432v\_{\rm cmd}+0.032263988 \\]

得到：

\\[ \boxed{ v\_{\rm cmd}^{\*}= \frac{ \dot u+0.433264281u-0.032263988 }{0.400421432} } \\]

从偏航动力学：

\\[ \dot r= 0.166118168v-0.544509453r+ 0.837536662w\_{\rm cmd}+0.000626529 \\]

得到：

\\[ \boxed{ w\_{\rm cmd}^{\*}= \frac{ \dot r-0.166118168v+ 0.544509453r-0.000626529 }{0.837536662} } \\]

这两个式子可以计算：

> 如果希望无人船按优化后的曲线运动，理论上需要向船舶发送什么速度命令和角速度命令？

但是还有一个关键条件。

### 9.4 横向动力学一致性不能忽略

你的横向动力学为：

\\[ \dot v= -0.313324916v -0.006741061r -0.407958500w\_{\rm cmd} -0.000993619 \\]

由于系统只有两个控制输入，而速度子系统有三个状态，不能认为任何光滑的 \\(x,y,\psi\\) 曲线都能独立实现。

因此，反求控制后必须计算横向动力学残差：

\\[ \boxed{ \begin{aligned} e_v={}& \dot v+0.313324916v\\\ &+0.006741061r\\\ &+0.407958500w\_{\rm cmd}^{\*}\\\ &+0.000993619 \end{aligned} } \\]

对于严格满足辨识模型的轨迹：

\\[ e_v(t)=0 \\]

但实际离散采样以及模型误差下，可以允许合理的小残差，并通过完整动力学重积分验证轨迹能否被复现。

必须同时满足：

\\[ v\_{\rm cmd,min}\le v\_{\rm cmd}^{\*}(t) \le v\_{\rm cmd,max} \\]

\\[ w\_{\rm cmd,min}\le w\_{\rm cmd}^{\*}(t) \le w\_{\rm cmd,max} \\]

以及必要的命令变化率、船体状态和安全约束。

这是把 B 样条和真实无人船动力学连接起来最重要的数学步骤。

这组反求关系来自你给出的线性命令动力学，而不是适用于任何船型的通用逆动力学公式。

## 十、方案 B：把船舶动力学直接放进 B 样条优化

如果后续要做更加严格的动力学轨迹优化，建议考虑以下两种实现。

### 10.1 方法一：状态 B 样条加动力学残差

将位置和航向定义为独立但具有共同时间参数的 B 样条：

\\[ x(t)=\sum_i N_i(t)Q\_{x,i} \\]

\\[ y(t)=\sum_i N_i(t)Q\_{y,i} \\]

\\[ \psi(t)=\sum_iN_i(t)Q\_{\psi,i} \\]

然后利用上一节公式恢复：

\\[ u(t),v(t),r(t) \\]

再反求：

\\[ v\_{\rm cmd}^{\*}(t),w\_{\rm cmd}^{\*}(t) \\]

构建动力学残差代价：

\\[ \boxed{ J\_{\rm dyn}= \int_0^T e_v(t)^2dt } \\]

加入优化器总代价：

\\[ \boxed{ J= w_sJ\_{\rm smooth} +w_oJ\_{\rm obstacle} +w_dJ\_{\rm dyn} +w_uJ\_{\rm control} +w_rJ\_{\rm reference} } \\]

这里的 \\(J\_{\rm control}\\) 可以对反求命令的越界量进行惩罚。

但必须明确：

有限权重的残差惩罚，只是鼓励满足动力学，并不保证严格满足动力学等式。

如果要严格保证，应该使用等式约束：

\\[ e_v(t_j)=0 \\]

并考虑采样点之间的误差与独立验证。

该方法能够较多地保留原 Fast-Planner 的位置控制点优化思路，但需要实现新的梯度或自动微分，并处理角度连续性。

### 10.2 方法二：使用控制输入 B 样条

我认为这是最终更值得研究的一条路线。

不是直接优化任意位置曲线，而是优化连续控制输入：

\\[ \boxed{ \mathbf U(t)= \sum\_{i=0}^{n}N_i(t)\mathbf C_i } \\]

其中：

\\[ \mathbf C_i= \begin{bmatrix} C\_{v,i}\\\C\_{w,i} \end{bmatrix} \\]

对应控制命令：

\\[ v\_{\rm cmd}(t)=\sum_iN_i(t)C\_{v,i} \\]

\\[ w\_{\rm cmd}(t)=\sum_iN_i(t)C\_{w,i} \\]

再通过：

\\[ \dot{\mathbf X}=f(\mathbf X,\mathbf U(t)) \\]

进行数值积分，得到实际船舶轨迹：

\\[ \mathbf X(t) \\]

其优化形式为：

\\[ \boxed{ \begin{aligned} \min\_{\mathbf C_i,T}\quad& J\_{\rm goal} +J\_{\rm obstacle} +J\_{\rm control} +J\_{\rm smooth} +w_tT\\\ \text{s.t.}\quad& \dot X=f(X,U(t))\\\ &U(t)\in\mathcal U\_{\rm valid}\\\ &X(t)\in\mathcal X\_{\rm safe} \end{aligned} } \\]

这样生成的轨迹始终来自同一个动力学模型。

不过，它需要改变原始优化器的优化变量，还要解决轨迹积分对控制点的梯度计算问题。可以采用灵敏度传播、自动微分或多重打靶方法。

如果以“研究型、动力学一致的无人船规划器”为目标，我更倾向这一方案。

### 10.3 两种后端方案的实际选择

| 维度                    | 位置与航向 B 样条 | 控制输入 B 样条   |
| --------------------- | ---------- | ----------- |
| 与原 Fast-Planner 的复用程度 | 较高         | 较低          |
| 几何路径平滑                | 直接         | 通过动力学积分间接实现 |
| 船模一致性                 | 需要残差约束与验证  | 由积分模型构造     |
| 控制限幅                  | 通过逆动力学检查   | 更容易直接施加     |
| 实现难度                  | 中高         | 高           |
| 与已有前端轨迹的衔接            | 较直接        | 需要拟合原始命令序列  |
| 适合阶段                  | 第一版至中期     | 后期强化        |

需要强调，控制输入 B 样条也不是天然保证真实船舶安全。模型误差、执行器延迟、外界扰动和离散碰撞检查仍可能导致实际轨迹偏离预测。

## 十一、你目前模型中还存在几个需要核实的问题

这部分不能跳过，否则很容易出现“仿真规划有效，实船执行不正常”的情况。

### 11.1 零控制输入不一定意味着零速度

根据你的纵向动力学：

\\[ \dot u=-0.433264281u+ 0.400421432v\_{\rm cmd} +0.032263988 \\]

令：

\\[ v\_{\rm cmd}=0,\quad\dot u=0 \\]

得到稳态速度：

\\[ u\_{\rm ss}= \frac{0.032263988}{0.433264281} \\]

\\[ \boxed{u\_{\rm ss}\approx0.07447\ {\rm m/s}} \\]

也就是说，根据这个辨识方程，即使发送零前进命令，模型仍预测存在约 0.074 m/s 的纵向稳态速度。

这不一定代表实船真的在零命令下持续前进。

可能原因包括：

- 辨识数据包含流速或定位误差；
- 常数项吸收了其他未建模的影响；
- 低速区域并不符合当前线性模型；
- 零命令附近存在执行器死区或特殊控制逻辑。

因此，不能未经验证就把模型中的零命令等同于停船状态。

这个问题会直接影响终端停止条件、Shot Trajectory 和靠泊规划。

另外，你的 PDF 说明这些系数描述的是当前 `k` 条件下的命令响应。需要明确 `k` 代表什么、是否会随航速、负载或控制参数变化，而不能默认这些系数对所有航行工况都有效。

### 11.2 模型并未明确包含风浪流

你的 PDF 模型是经过数据辨识得到的命令响应模型，而不是完整的海洋环境扰动模型。

如果考虑海流，并且 \\(u,v\\) 定义为相对水体的速度，那么世界坐标速度应增加流速：

\\[ \dot x=u\cos\psi-v\sin\psi+V\_{c,x} \\]

\\[ \dot y=u\sin\psi+v\cos\psi+V\_{c,y} \\]

但如果原模型是在含流环境中使用对地速度直接拟合的，再加入相同的流速项可能造成重复计算。

所以目前不能直接加，需要先确认速度数据的坐标和参考系。

### 11.3 缺少的关键数据

你的 PDF 虽然给出了 11 个辨识参数和 19,804 行原始数据的说明，但没有提供以下内容。

| 缺少的信息                    | 影响              |
| ------------------------ | --------------- |
| `v_cmd`、`w_cmd` 的实际可用上下界 | 无法确定合法控制采样      |
| 不同命令下的最大实际 \\(u,v,r\\)   | 无法确定状态限制和启发式上界  |
| 船体实际长宽和安全裕度              | 无法精确建立碰撞模型      |
| 命令更新周期、延迟和变化率限制          | 无法验证快速命令切换是否可执行 |
| 11 参数辨识的测试工况和独立验证误差      | 无法确定模型的有效范围     |
| 定位、航向及速度估计误差             | 无法设置合理的动态安全裕度   |
| 规划场景是否允许倒车、原地旋转          | 决定运动基元采样范围      |
| 后端轨迹最终由什么控制器执行           | 决定前端输出和轨迹跟踪接口   |

这些不是必须全部收集齐才能开始开发，但其中控制输入范围、船体尺寸、命令周期和模型验证数据应当优先确认。

## 十三、我建议你按照四个阶段实施

## 1

先验证船模，不接入路径规划

建立独立动力学仿真器，输入命令序列，输出六维状态。使用直航、转向、S 弯和零命令等测试场景。

对比不同积分步长和真实记录，重点评估 1、2、5 秒等预测时间范围下的位置、航向和速度误差。

## 2

完成纯前端 USV Kinodynamic A\*

实现控制采样、状态传播、完整状态哈希、船体碰撞检查、启发式搜索。

先在空旷水面测试直线与转弯，再增加静态障碍和狭窄航道。

## 3

比较优化前后轨迹的路径偏差、航向变化、碰撞裕度、逆算控制输入和横向动力学残差。

如果优化结果不能由船模实现，则拒绝该结果，重新优化或回退到经过验证的前端轨迹。

## 4

强化完整避碰与轨迹优化

增加动态目标船预测、COLREGs 行为约束、短时终端连接和航道中心线约束。

根据测试结果决定是否把后端升级为控制输入 B 样条或带船模动力学等式约束的优化器，并对扰动和模型误差做鲁棒性验证。

## 最终结论

从你现有的基础出发，我不建议直接大改整个 Fast-Planner，而是采用以下技术路线：

第一步： 保留 Kinodynamic A\* 搜索框架，把前端完全改为使用你的六状态、双输入辨识船模。

第二步： 暂时移除双积分器启发式解析解和原始三次多项式 Shot，换成简单可靠的时间下界启发式，并先以完整运动基元搜索完成规划。

第三步： 保留 B 样条的几何平滑功能，但严格区分位置与航向，利用逆动力学、横荡残差和完整船模重积分检查优化结果。

第四步： 如果验证发现 B 样条频繁破坏可执行性，再升级为带动力学约束的轨迹优化，而不是依赖不断调整平滑度权重去掩盖这个问题。

我认为这是一条在工程改造成本、可验证性和最终动力学一致性之间更合理的路线。

目前最不应该做的是：同时修改状态方程、启发式、Shot、B 样条、COLREGs 和控制器。这样即使得到一条看似漂亮的轨迹，也无法判断它究竟是由正确的船舶动力学产生，还是仅仅经过几何优化后恰好看起来合理。
