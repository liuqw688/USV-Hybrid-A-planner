# 无人船改造协作要求

开始工作前，阅读 `docs/USV_MODIFICATION_LOG.md`。需要了解原始方案时阅读 `docs/USV_DESIGN_REFERENCE.md`。

- 保留 Fast-Planner 整体规划框架，在现有框架上逐模块、逐功能改造为无人船规划项目。
- 只实施用户当前指定的修改；原始方案中的建议和备选路线不是已批准的实现决定。
- 后端 A/B 路线、方案 B 内部两种实现、终端连接等尚未确定，不得自行选择。
- 修改前检查与已有实现及上下游接口的衔接。发现逻辑冲突、模型不一致或缺失条件，说明影响并提出建议；涉及方案决策时由用户决定。
- 每次修改完成后，必须在 `docs/USV_MODIFICATION_LOG.md` 追加记录，不覆盖历史。
- 用户要求此工程不在本地电脑编译；采用源码核查、静态检查或不编译工程的数值检查，不启动构建。
- `docs/USV_MODIFICATION_LOG.md` 只记录 Fast-Planner-ROS2 文件夹内的代码和配置修改，包含日期、用户要求、文件与函数、修改内容及原因、与此前改动的衔接和待定决定；不要记录测试内容。
- 测试条件、方法、实际验证结果和问题记录在 `docs/测试记录.md`；用户要求保留 059 及以前的改造记录原文。
- 回复中逐处解释修改，提供可点击的文件位置，让用户能够逐一检查；不将未验证内容描述为已通过。
- 交接资料使用项目相对路径；换电脑时应携带整个项目及上述记录、方案与本文件。
