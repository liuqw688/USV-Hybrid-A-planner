# 中间航点交接、顺序降速搜索与短距离转弯修复

## 修改范围

本次修改 Hybrid A* 的调度、连接候选和搜索预算；未修改 MPC/DWA 控制器、船舶动力学系数、航点 8 m 切换门槛或避碰安全距离。规划从实测位置、艏向及 `u/v/r` 开始，没有用速度或角速度外推起点来补偿搜索延迟。

## 1. 中间航点为何会出现等待

全局 A* 发布固定任务并逐个发布活动航点。原先 Hybrid 的新目标回调只设置标志，等下一次 1 Hz 监测才启动后台搜索；如果上一航点的搜索尚未退出，其过期结果完成后，还要等下一次监测才能启动新任务。

现在，新目标回调立即投递后台搜索，旧搜索使用取消令牌退出。过期结果一旦回收，立即按最新实测状态启动最新目标，且先检查任务编号，再处理提速搜索结果，避免旧提速任务干扰新航点。

同一次全局任务的前进航点交接保留并刷新上一条**仍然安全**的路径，直到新段通过最新状态与碰撞复验。不是无条件锁定旧路径：障碍物使剩余旧路径不安全时仍撤销路径，新任务取消也仍清空。结果采集定时器维持 50 ms，因此完成的后台结果不用等下一次 1 Hz 监测。

流程：

```text
全局A*在8m范围内切下一航点
  → 立即取消旧搜索、投递新目标
  → 新搜索未完成：复验并刷新旧安全路径
  → 新搜索完成：任务编号检查 → 最新船位可接入检查 → 安全复验
  → 发布新路径和配套参考速度
```

## 2. 每一种参考速度尽快尝试

保留 10 个从 4.0 到 1.2 m/s 的均匀递减速度，当前速度尝试结束后才进入下一速度，不并行竞速。新增参数：

```yaml
speed_sampling.stage_time_limit: 0.12
```

这是每个非最低速阶段的搜索预算（秒），在既有总预算中分配；最低速保留该主航道/可安全借道阶段剩余预算，用于困难的格点搜索。减小值会更快进入低速，但可能让可行的高速格点解来不及找到；增大则高速搜索更充分但交接延迟增加。建议先使用 0.12，复杂障碍下可尝试 0.18～0.25，不建议把总预算盲目加大。

大河图的二维引导场与参考速度无关。以前它可能在每个短速度阶段中超时、清空并重建，消耗了多次扫描整图的时间。现在它在总任务预算和取消令牌约束下构建一次，后续速度复用。**共享预处理不计入单个速度的 0.12 秒上限，但计入任务总预算**；不能把该参数理解为端到端交付保证。地图变化仍使缓存失效。

正常航道仍先尝试全程宽弧连接。若失败，在主航道内也允许快速单向 C 弯候选；格点搜索、低速与必要借道回退均保留。

航道中央窄带的宽弧候选失败后，先尝试整条主航道内的宽弧候选，避免把“无法始终待在中央窄带”误当成“该速度不可行”。仍要求主航道内、无碰撞；中央窄带依然优先。

普通宽弧连接接近端点时也缩短积分步长，避免一个较长的运动基元跳过端点验收范围，误以为该参考速度不可行。

## 3. 约20m、正交艏向目标

转弯连接不再为了等侧滑 `v` 和转艏率 `r` 衰减到近零，先强迫船直航很长一段距离。直接保留实测六状态入弯，转弯中逐步积分欠驱动模型。低速起步仍有短加速过渡。

入弯前的直段会改变纵向速度及残余侧滑，不能把基于旧状态计算的前后直段长度直接套用。新增少量预测迭代修正；最终输出仍逐段执行原碰撞、航道和 COLREG 检查，不直接挪动几何路径点。转弯角也按实际入弯艏向重新计算。

近距离任务也可以尝试时间受限的引导连接，不再直接跳过它。优先单向 C 弯，但若位置和末端艏向在几何上无法由单一 C 弯满足，则保留必要的多弧路径；无法安全满足时不能强行发布。

## 4. 测试与操作

已添加 `test_river_handoff_ros.py`：在独立 ROS 域 185 中启动真实 `river_chart` XML 河图、膨胀地图、航道管理、全局 A*、Hybrid、未修改的 MPC 和欠驱动仿真。目标以 `map` 坐标发送，默认起点 `[-270,-270]`，目标 `[-324,-101]`，全局路径包含起点、一个中间航点和终点。验证实际到达第一个航点后第二段交付、交接期间是否空路径以及全局路线是否只发布一次。

生成记录放在工作空间 `artifacts/river_handoff_update/`，包括各节点日志、`river_result.json`、实测状态 `tracking.csv`、两段规划 CSV 和实际河图上的 `river_handoff.png`。这是仿真验证，不是实船安全认证，未覆盖所有航道/动态交通组合。
